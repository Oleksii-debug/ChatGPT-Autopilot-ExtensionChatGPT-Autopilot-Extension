# 11.0.9 — live regression report, 2026-10-02T00:54+02:00

Three private 11.0.8 diagnostic reports generated 2026-10-01 22:38–22:39 UTC were analyzed locally. They are not bundled or published. Report A has five stopped scenario chats, one eventually confirmed send and completed response, and repeated ambiguous Send/frozen observations. Report B has five stopped chats and zero confirmed sends despite five physical attempts, followed by 45-second acknowledgement expiry. Report C shows six current confirmed sends across five waiting chats and no completed responses in the snapshot; its retained events contain many `ASSISTANT_RESPONSE_STREAMING` and `ASSISTANT_RESPONSE_TAB_FROZEN` results. A local optimistic append is not server receipt. The reports cannot establish whether all physical attempts reached the server.

The Send code path in 11.0.8 activated hidden form-submit tabs only when the configured post-Send dwell was positive. All three snapshots recorded 0 ms dwell. Thus their hidden form submits could finish with `messagesAfter=0`, `mainExactMatches=0`, `visibility=hidden`, while the page showed a Stop control. This is an observable verification gap, not proof of a failed server request. Scenario Send now activates its exact owned tab before submitting, even at 0 ms dwell; if activation fails it returns a no-effect result rather than clicking. Existing per-window lease and physical Send deduplication remain.

The response probe in 11.0.8 returned immediately for Chrome-frozen tabs, without ever waking them; for long-lived background generation the content could remain stale. The probe now activates at most one owned tab in a window per 15 seconds, reads it while awake, and conditionally restores the prior active tab. It never creates/navigates a chat to wake it. After 90 seconds of waiting it may refresh an unfrozen background tab the same way. User-driven focus changes are respected. This is a bounded recovery mechanism, not a claim that every response will be visible in every ChatGPT account.

During development a proposed URL-only send acknowledgement failed the pre-existing negative regression case and was removed. The strict operation-bound user append and current APSTEP response correlation are preserved. This matters because silently counting a client transition as a send would reproduce the user's false counters.

Risk: Chrome may continue freezing background tabs, and a pool may take several bounded observation cycles. Activating a tab briefly changes the active tab inside its bound window; the previous selection is restored when safe. Tests cover the modeled Chrome and DOM paths, not a physical Windows Chrome profile. This release requires a live account test before saying the scenario is fully repaired.
