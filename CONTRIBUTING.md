## Development workflow

These contribution rules supersede earlier repository guidance on work ownership, parallel changes, integration order, and CI waits.

- Keep independent work moving while other branches, reviews, or CI runs are pending. Record outstanding checks and choose a non-conflicting task, or reconcile and rebase overlapping changes.
- Coordinate concurrent changes through assignments and conflict tracking. Assignments are advisory, and the repository imposes no fixed limit on contributors, work in progress, branches, or pull requests.
- Follow dependency order when integrating changes. Implementation, testing, accessibility, packaging, documentation, and recovery work can proceed independently.
- Open, update, and merge pull requests when the evidence supports the change and GitHub permissions and branch protections allow it. An exclusive integration owner is optional.
- Document blockers and continue with any safe, independent work available. Save verified progress, remaining work, and the evidence behind each checkpoint in commits, pull requests, or the applicable plan register.
- Preserve product correctness, security, privacy, data integrity, accessibility, licensing, and accurate test and release evidence.
