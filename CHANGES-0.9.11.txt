ChatGPT Автопілот 0.9.11 — ORDINARY SESSION RECOVERY / LIFECYCLE HOTFIX

КРИТИЧНІ ВИПРАВЛЕННЯ
1. BOUNDED ORDINARY AMBIGUOUS RECOVERY
- Ordinary Session більше не може нескінченно продовжувати verificationDeadline після SUBMISSION_UNCERTAIN.
- Після bounded verification window unresolved фізичний Send не повторюється; operation стає FAILED_SAFE і наступний normal cycle може продовжити роботу.
- Managed Scenario/Orchestration safety contract не послаблено.

2. TAB OWNERSHIP / CLEANUP
- Fresh launch surface / або /g/<slug> після Send може перейти у /c/<conversation> без втрати ownership тієї самої extension-owned вкладки.
- Recovery повторно використовує початкову owned вкладку замість створювати orphan duplicate.
- TAB_NAVIGATION_TIMEOUT і TAB_NAVIGATION_URL_MISMATCH в open-close режимі інвалідовують/закривають dead owned tab; наступний retry отримує чисту вкладку.

3. STOP / PAUSE / CONTINUE / START
- Pause -> Continue/Resume: підтримується.
- Pause -> Start: тепер трактує Start як безпечне продовження тієї самої Session без reset прогресу.
- Stop -> Start: підтримується.
- Stop -> Continue/Resume: тепер підтримується замість помилки "Only a paused session can be resumed".
- Unresolved SUBMITTING/AMBIGUOUS evidence не губиться при Pause/Stop; продовження відновлює recovery state.

4. USER TIMING AUTHORITY
- Інтервал запуску Session не змінено і не форсується релізом 0.9.11. Його обирає користувач.
- Busy-check також лишається окремим user setting. Busy=3 означає 3 секунди до повторної перевірки busy/generating chat, а не інтервал запуску і не timeout відповіді.

5. RELEASE REGRESSIONS
- Додано ordinary-night-liveness до reliability release gate: 6 Ordinary Sessions, довгий virtual-night run, injected ambiguous Send і dead-tab timeout faults.
- Додано regressions для bounded uncertain settlement, root->conversation tab ownership, dead-tab cleanup, Stop->Resume та Pause->Start.
