Пілот 11.0.5 High — продовження Agent owner view

- Завершено збережений Agent checkpoint 4cbc6d1 поверх виправлень навантаження 11.0.4.
- Запізнілі SELECT/list/lifecycle/Delete/permission відповіді не перемикають актуально вибраного агента, не відновлюють видаленого і не запускають іншого агента після дозволу для попереднього.
- Stop/Pause залишаються окремими командами під час довгого Run. Запізніле завершення Run не стирає показаний Stop.
- Повторний клік тієї самої незавершеної команди об'єднується, включно з Create та Approval.
- Один незавершений запит списку на сторінку. Таймаут UI не дозволяє накопичувати ще запити до незавершеного Chrome message. Оновлення раз на 5 секунд лише у видимій Agent-панелі; під час Create/Delete фонова перевірка пропускається; під час довгого Run/Specialist прогрес продовжує оновлюватися.
- Список зі старої ревізії після mutation не приймається; максимум один додатковий свіжий read. Нативні option не перебудовуються без зміни списку/статусу.
- Підтверджене Create має окремий текстовий результат та ID. Подальший збій Start/читання не позначає вже створене завдання як не створене. Definition create залишається STOPPED і не запускає виконання.
- Новий текст follow-up не стирається запізнілим підтвердженням попереднього тексту.
- Specialist progress читається зі збережених ownership/dispatch/automation/plan states. PROVIDER_SUCCEEDED або COMPLETED самі по собі не є незалежною перевіркою. RECONCILE, MANUAL_REVIEW, RETRY_WAIT, FAILED/CANCELLED показуються окремо; VERIFIED потребує збереженого VERIFIED ownership та plan node з evidence.
- Результат команд має semantic role=status; його не стирає періодична перемальовка.

Збережено всі сценарні/спрощені виправлення 11.0.4, фізичну вкладку на цикл та 35/45 хвилин, до трьох advisory спроб High. Змінена лише UI-проекція поверх чинного Core; другий runtime чи scheduler не створювався.

Повна Agent-платформа не оголошується готовою. Два старі набори з 33 невідповідностями відтворюються на базовій 11.0.4: вони очікують відсутні/перейменовані autoPrepareSpecialistHandoff та setSpecialistProviderConfig APIs і окремі reusable model-default controls. Це окрема робота; у цьому випуску їх не приховано й не позначено PASS. Фізичні Windows/Chrome/NVDA та зовнішній provider тут не перевірені.
