ChatGPT Автопілот 0.9.0 — MULTI-AGENT ORCHESTRATION V2 CANDIDATE

ГОЛОВНА ЗМІНА
- Autopilot перетворено з Remote Dispatch executor на зовнішній durable multi-agent orchestration harness.
- Autopilot не удає AI: він deterministic scheduling/runtime/control plane; Coordinator ChatGPT приймає reasoning decisions; disposable Worker chats виконують окремі tasks; GitHub є live technical truth і machine-readable control path.
- Existing Session/Task scheduler, Chrome interaction, durable Send checkpoints, recovery, rate-limit/backoff, tab ownership і release packaging перевикористані; другого scheduler немає.

COORDINATOR LIFECYCLE
- Durable coordinator generation, turn counter, turnId, lease/single-flight, chat URL, delivery evidence, assistant baseline і retry/backoff state.
- Один project/profile має не більше одного coordinator reasoning turn одночасно.
- Completion/watchdog/recovery events durable, deduplicated і coalesced while coordinator BUSY.
- Coordinator turn positively delivered exactly once: deliveredTurnId не дозволяє re-arm того самого tick після restart/probe.
- Default maxCoordinatorTurns=10, configurable. Rotation створює fresh generation + clean chat + bounded machine handoff і RECOVERY_RECONCILE event.

ROLLING WORKER POOL
- Durable worker states: QUEUED, LAUNCHING, ACTIVE, BUSY, COMPLETED, FAILED, BLOCKED, RATE_LIMITED, STALE, CANCELLED, SUPERSEDED, MANUAL_REVIEW.
- Default worker launch mode FRESH_CHAT; one independent task -> one fresh ChatGPT chat.
- Completion-driven refill: будь-який terminal worker негайно створює coordinator event; система не чекає інших workers.
- Coordinator може створювати великий backlog без штучного ліміту кількості tasks; фактичний запуск обмежує owner policy.
- Owner policy окремо задає absoluteMaxWorkers, maxLaunchesPerWindow, launchWindowSeconds і minimumWorkerLaunchIntervalMs. Coordinator отримує ці локальні межі в кожному tick, але не може їх перевищити.
- Exact-once task/generation/exact_once_key, dependencies, not_before/expiry і conflict_key gates.
- CANCEL/SUPERSEDE queued work не force-kill-ить healthy in-flight worker; supersede request для active worker зберігається fail-safe.

WATCHDOG / SELF-HEALING
- Periodic watchdog (~5 хв default) лише RECONCILE; не створює work сам.
- Watchdog-only coordinator prompt прямо дозволяє NO_ACTION/KEEP_RUNNING і забороняє spawn лише через tick.
- Healthy long BUSY worker не стає stale від самого віку.
- Повторні completion-probe failures past threshold створюють WORKER_STALE_CANDIDATE, але не звільняють slot і не запускають blind successor.
- Worker/coordinator rate-limit створює project-level backpressure; queued work не fan-out-иться до retry deadline.
- Watchdog під coordinator backoff coalesce-иться без hot-loop alarms.

GITHUB CONTROL V2
- Новий `src/core/orchestration-v2-github.js`: read-only GitHub control provider через api.github.com.
- Preferred stable canonical Issue comment; discovery mode шукає marked control на актуальних останніх сторінках навіть у Issue зі 100+ коментарями, після знаходження переходить на direct Comment ID.
- Exact marker `<!-- CHATGPT_AUTOPILOT_CONTROL_V2 -->`, schema_version=2, project_id, revision, coordinator_generation, timestamps, mode, actions.
- Strict allowlist actions: NO_ACTION, SET_DESIRED_CONCURRENCY, ADD_TASKS, CANCEL_QUEUED_TASKS, SUPERSEDE_TASKS, PAUSE, RESUME, ROTATE_COORDINATOR, CONTROL_NOTE.
- Remote control fail-closed: invalid integer/revision/generation/priority, malformed JSON, wrong project/generation, stale/expired revision або mixed NO_ACTION не породжують workers.
- Read-only control test перевіряє GitHub feed до coordinator lease без state mutation.

SERVICE WORKER / RECOVERY
- `OrchestrationV2Controller` wired into production service worker with single-flight alarm `autopilot-orchestration-v2-wake`.
- Startup order: durable Core recovery -> orchestration reconciliation -> Core execution. Cold start не має права blind-spawn before recovery.
- Existing Core executor remains sole browser Send authority.
- Active worker chats залишаються відкритими для completion monitoring; terminal worker tab закривається. Durable coordinator conversation URL зберігається між turns і не губиться при tab loss/restart.
- Assistant completion probes охоплюють увесь дозволений active pool, включно зі stress-case 100 workers, без starvation.
- Restart recovery verified for pending terminal event, coordinator rate-limit lease, worker rate-limit/backpressure, lost tab hints and exact-once control/task indexes.
- Lost tab hint does not erase stored coordinator/worker chat URL or duplicate Session/Send.

UI / OBSERVABILITY
- Options розділено на три основні режими: Сеанси / Оркестрація / AI. Внутрішні coordinator/worker Sessions приховані зі звичайного списку.
- Orchestration UI має короткі професійні labels, owner limits, Master/Tick prompts, Test GitHub control, reconcile, Emergency STOP і JSON template/import/export без auto-start після імпорту.
- Status exposes project, coordinator generation/URL/turns/lease, desired/effective/max workers, worker counts, pending events, last revision/watchdog/provider/backoff.
- Legacy Remote Dispatch V1 згорнутий як Legacy усередині Orchestration і не конкурує з основними режимами. Legacy Remote Dispatch V1 and V2 cannot be enabled simultaneously.
- Provider/capability registry + InteractionProviderRouter ізолюють ChatGPT Web transport від Core. Нові API/local/site providers можуть додаватися adapter-ами без другого scheduler.

RUNTIME HARDENING CHECKPOINT — 2026-09-12
- Fixed a durable-state lost-update race in `OrchestrationV2Controller.materializeQueuedWorkers()`. Worker materialization now runs inside the serialized orchestration repository update chain instead of loading runtime, mutating Core, then saving a potentially stale runtime snapshot.
- Core remains the sole browser Send authority; the change only makes orchestration binding/launch-accounting atomic with respect to concurrent coordinator/watchdog/completion/control mutations.
- Added regression: `worker materialization cannot overwrite a concurrent durable coordinator event`. It intentionally blocks Core materialization, queues a concurrent WATCHDOG_RECONCILE event, then proves both the LAUNCHING worker transition and the event survive.
- Exact post-fix full automated matrix: 667/667 PASS. Practical Chromium UI/accessibility and ChatGPT-like phased interaction gates: PASS.
- This is runtime hardening of the 0.9.0 candidate, not a HUMAN_TESTED/NVDA_VERIFIED/released claim.

Exact-once reservation is preserved so a retry requires a fresh justified coordinator identity/generation rather than silently replaying expired authority.
- Added deterministic controller regression for expired-before-launch backlog behavior.
