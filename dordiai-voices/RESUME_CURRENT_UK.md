# Продовження dordiai-voices

Користувач дозволив автоматичні рішення, субагентів і некомерційні ресурси; додаткові запити про це не потрібні. Доручення — кінцевий продукт за FINAL_PRODUCT_SPEC_UK.md, а не лише цей запис.

Локальне середовище стало недоступним під час роботи. Перед цим у Git збережено всі 179 файлів замороженого джерела dev.6 та повний стиснений знімок джерела. Windows GitHub Actions працює незалежно. Поточний повний запуск: 45000863624. Не вважати його успішним: рушії, структура символів і явно ввімкнений спільний MMS уже повідомили збій; протокол NVDA ще виконується. Отримати завершені журнали й виправляти конкретні причини.

Ядро dev.6 локально повністю перевірено за складом: 1 767 406 268 байтів, SHA-256 ee60a000b3ea4387c2baf2afbbb252fd886b603d4e532220e62f29bf9dc465c8; установлений обсяг 2 130 470 392 байти. Це не підтвердження працездатності чи готовий публічний випуск. Початковий комплект містить три мови й 45 дозволених профілів. Вісім виключених профілів заблоковані. Ресурси ширшого каталогу встановлюються окремо.

Знімок: evidence/source_snapshot_0.13.1-dev.6.json.gz, SHA-256 2dbcaef3e98342b6143cb604efd0f4d8ad95a90aec9279f95c551b3a53277b56; дерево джерела 8e8fe6056698395a885030bcf7df4f957e8c62283af9c8558d54dce081210d8f. Базову акустичну частину можна відновлювати зі збережених чотирьох ZIP резервної копії core dev.4 та засобів restore_core_backup.py/recover_core_baseline.py. Точний збіг відновленої dev.5 вже доведено. Відновлена dev.6 теж зібрана з тим самим розміром та складом, але остаточне порівняння SHA перервала недоступність середовища; не позначати його завершеним.

У Windows доведено причину попереднього збою marisa_trie: шлях до PYD довжиною 264 символи. Обидві контрольні спроби через розширений простір імен відкрили той самий файл і український словник. У dev.6 додано нормалізацію шляхів приватного процесу; новий повний протокол виявив додаткові регресії, їх ще слід розібрати. Безпечне завершення процесу перед заміною mmap-файла пройшло справжню Windows-перевірку. Спільний MMS залишається вимкненим за замовчуванням.

Звіт субагента про всі 29 моделей перед збоєм середовища: вихідний і перетворений PCM побітово однакові для контрольних символьних послідовностей; це не приймання природної вимови. Повний новий звіт і окремий скрипт залишилися в недоступному робочому каталозі, тому поки збережено лише це повідомлене резюме. Відтворити перевірку після відновлення виконання. Раніший докладний тримовний прототип та 16 нових регресій уже в Git.

Готовність продукту залишається false: мовні прогалини, звичайні назви символів, швидке читання нових слів, вимова та реальний аудіовихід мають відкриті вимоги. Не підмінювати їх успішним імпортом, тестовим вихідним приймачем чи повторенням закешованого слова.

Уточнення після dev.7 і повторного запуску 45003764603: три початкові рушії та обидва шляхи MMS (оригінальний/спільний, із перетворенням голосу) пройшли фактичні Windows-перевірки. Повні 100+100+100 вимірювань NVDA завершилися без помилок/тайм-аутів. Це тестовий приймач PCM: фізичне звучання лишається неперевіреним. Аварійне перемикання на справжній eSpeak, збереження профілю, завершення старого драйвера та ненульовий PCM повідомлення пройшли повторну перевірку після виправлення SpeechMode у тесті. Ядро dev.7: 1 767 407 702 байти, SHA-256 14481b1cc0f9d01ae30845647f8ef2c31a8d5bbbfcc97bc6e10e345fb20e473b. Точні JSON звіти dev.7 збережено у evidence/windows_dev7_run_45002685422.json.gz, SHA-256 1a923c1f0493f9ced9b02ec540f3ca4731f25ed7480734561831897dc49eea5d.

Ще два вибіркові додаткові рушії мають збій шляху старого C API eSpeak. Готуються незалежно перевірені кандидати для dev.8: межа C data-parent/espeak-ng-data з перевіреним ASCII-аліасом; увімкнення перевіреного MMS за замовчуванням; вузьке аварійне відновлення лише для справжньої відсутності обов’язкового ресурсу RuAccent. Не зараховувати кандидатам виконання до CI. Наступний пробний запуск має також виміряти всі основні літери/цифри/символи, а не лише повтори однієї прогрітої літери.
