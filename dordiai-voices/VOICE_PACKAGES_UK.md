# Додавання та заміна голосів без переписування синтезатора

Пакет голосу — це підготовлені дані для відомого акустичного рушія. Він не містить Python-коду, DLL або окремої копії всіх спільних моделей. Мовні словники, маршрутизація, налаштування NVDA й керування чергою залишаються в ядрі.

## Що вже реалізовано

- Один формат `voice-package.json`, версія формату 1.
- Незмінний ідентифікатор голосу, версія, назва, рушій і версія його адаптера, фактичні мови/стилі та походження матеріалу.
- Інвентар файлів із призначенням кожного ресурсу, розміром і SHA-256.
- Повторюване створення ZIP із підготовлених даних, перевірка всіх хешів, установлення через тимчасову папку та атомарне перемикання активної версії.
- Окремі папки версій, перевірене повернення до попередньої версії, видалення тільки вибраного голосу.
- Підключення підготовлених даних до Holos, OpenVoice, OmniVoice та наявних адаптерів Pocket English/Russian і широкого мовного каталогу.
- Вкладка «Пакети» у налаштуваннях: установлення, список голосів і мовних ресурсів, видалення, вибір попередньої версії голосу. Після зміни пакетів потрібен перезапуск NVDA, щоб очистити стан акустичних рушіїв.

## Повторювана процедура

Усі нові голоси одного типу використовують ту саму команду й рецепт. Рецепт визначає ідентичність і підготовлені ресурси; код не змінюється під конкретну людину.

Приклад рецепта для Holos/OpenVoice-профілю:

```json
{
  "voice_id": "new_voice",
  "name": "Новий голос",
  "version": "1.0.0",
  "engine": {"id": "holos", "compatibility_version": 1},
  "languages": ["uk"],
  "styles": ["neutral"],
  "provenance": {"source": "Опис власного підготовленого матеріалу", "license": "Умови використання"},
  "requires": [],
  "roles": {
    "profile-holos.npy": "holos_profile",
    "profile-conversion.npy": "target_embedding"
  }
}
```

Команди з кореня `dordiai-voices`:

```text
python tools/voice_packages.py prepare --source prepared --recipe recipe.json --manifest prepared/voice-package.json
python tools/voice_packages.py create --source prepared --manifest prepared/voice-package.json --output new_voice-1.0.0.dordiai-voice
python tools/voice_packages.py inspect new_voice-1.0.0.dordiai-voice
```

Далі файл установлюється через доступне вікно «Пакети». CLI також має `install`, `list` і `activate`; для депо без запущеного синтезатора можна окремо передати інвентар сумісних рушіїв і спільних ресурсів. Установлення до депо не є доказом акустичної якості.

## Призначення підготовлених файлів

- `holos_profile`: масив NPY `(1, 256)` для Holos.
- `target_embedding`: масив NPY `(1, 256, 1)` для перетворення тембру; використовується також широким мовним адаптером.
- `english_embedding`: необов’язковий окремий відкалібрований NPY для англійського носія OpenVoice.
- `pocket_english_state`: підготовлений NPZ зі станами, що відповідають спільній моделі Pocket English.
- `pocket_russian_prompt`: підготовлений Safetensors; його ім’я повинно точно збігатися з `voice_id` і закінчуватися `.safetensors`.
- `native_delivery`: необов’язковий JSON із налаштованими `en`/`ru` параметрами gain, tempo, seed і temperature.
- `reference_audio` і `reference_text`: аудіозразок та правильна транскрипція для адаптера OmniVoice.
- `native_letters_index` і `native_letters_audio`: індекс та суцільний PCM-банк назв літер саме цього голосу.
- `native_commands_index` і `native_commands_audio`: необов’язковий індекс та PCM-банк коротких команд саме цього голосу.

Необхідні ролі залежать від рушія. Holos вимагає `holos_profile`, OpenVoice — `target_embedding`, OmniVoice — обидва референсні файли. Наявність профілю Holos не означає автоматичної наявності нативних Pocket-профілів іншою мовою. Наявність довільного NPY не доводить, що це правильний вектор; адаптери перевіряють форму й скінченність значень, а вимова та тембр перевіряються окремо.

Якщо потрібен додатковий спільний пакет, `requires` містить його точний `id` і `version`. Під час установлення в синтезатор вони звіряються з реєстром мовних ресурсів. Голос із відсутньою залежністю не повинен потрапляти до доступного каталогу.

## Межі підтримки

Цей інструмент пакує вже підготовлені профілі, стани та звукові дані. Він не видає копіювання WAV або довільний набір чисел за навчений якісний голос. Підготовка нового акустичного профілю з записів потребує процедури відповідного рушія; окрема фабрика голосів не підміняється цим пакувальником.

Поточні інтегровані адаптери заявляють тільки нейтральну манеру. Пакет із непідтриманою емоцією не активується як нібито емоційний голос. Новий рушій зі справжніми стилями підключається одним адаптером для всього сімейства голосів.

## Підготовка власних банків літер для нового голосу

`tools/prepare_voice_banks.py` працює у Windows з уже встановленим голосом Holos-сімейства та справжнім упакованим акустичним робітником. Ця команда не використовує підставний звук і не навчає новий голос із довільного WAV.

Приклад повторюваного конвеєра з кореня репозиторію:

```text
python tools/prepare_voice_banks.py --package-root C:\NVDA\userConfig\addons\dordiai-voices --voice new_voice --version 1.1.0 --output C:\DordiaiPrepared\new_voice-1.1.0 --languages uk,en,ru
python tools/voice_packages.py prepare --source C:\DordiaiPrepared\new_voice-1.1.0 --recipe C:\DordiaiPrepared\new_voice-1.1.0\recipe.json --manifest C:\DordiaiPrepared\new_voice-1.1.0\voice-package.json
python tools/voice_packages.py create --source C:\DordiaiPrepared\new_voice-1.1.0 --manifest C:\DordiaiPrepared\new_voice-1.1.0\voice-package.json --output C:\DordiaiPrepared\new_voice-1.1.0.dordiai-voice
```

Шлях до NVDA у прикладі потрібно замінити фактичним. Необхідні мови мають бути заявлені встановленим голосом і мати придатні моделі. Без `--languages` команда готує його початкові базові алфавіти. Для експорту вбудованого профілю додатково передається `--license` з фактичними умовами походження матеріалу; умови використання інструмент не вигадує.

У нову папку копіюються підготовлені профільні дані, створюються банки, звіт і новий рецепт. Каталог установленого голосу, його активна версія та попередні пакети не змінюються. Існуюча папка результату або вже встановлена версія не перезаписується. При невдачі залишається окрема папка `.preparing-…` зі звітом та частковими даними; вона не активується як готовий голос.

Для перевірених власних списків літер або коротких команд використовується `--entries-json`. Наприклад:

```json
[
  {"kind":"letter", "language":"uk", "lookup_text":"б", "text":"бе", "semantic_kind":"spoken_name", "aliases":["бе"], "source_kind":"letter_name"},
  {"kind":"command", "language":"uk", "name":"Зберегти", "text":"Зберегти"}
]
```

Цей параметр також приймає безпосередньо `models/CharacterNames/<код>.json` у форматі `dordiai-character-name-sources`, версії 1. Інструмент перевіряє формат і мову та бере тільки явно підготовлений список `bank_entries`. Інвентар відсутніх назв і окремі фонетичні описи автоматично на аудіозавдання не перетворюються.

`lookup_text` — ключ, який передає драйвер; старе поле `name` теж приймається. `text` — текст для синтезу. Перевірена назва має явну позначку `semantic_kind: spoken_name`: вона читається буквально як звичайний текст, без повторного перетворення назви на іншу назву символу. Фрагмент при цьому залишається в банку літер. `aliases` дають додаткові ключі до того самого PCM без повторної генерації чи копіювання звуку.

Без цієї явної позначки завдання для літери вважається `raw_character`: неперевірений знак передається до мовного фронтенда в режимі символу і відхиляється, якщо правильної назви немає. Фонетичні описи на зразок слів міжнародного радіоалфавіту не зараховуються як звичайні назви літер. Поля `source_kind` та `source_id` зберігають походження перевіреної назви.

У базових алфавітах назви беруться безпосередньо з коду драйвера, без окремої копії списків. Для інших писемностей потрібно передати перевірений список, а не вигадувати назви символів.

Аудіо має формат 24000 Гц, один канал, 16 біт little-endian. Кожен фрагмент обмежено вісьмома секундами. Індекс містить ідентичність голосу, формат звуку, ознаку завершеності, мовні ключі, зміщення та розміри. Драйвер читає перевірений банк перед запуском моделі, зокрема для базових мов і введення з клавіатури; відсутня назва повертається на синтез тим самим налаштованим голосом. Банк іншої людини, незавершений індекс і невідповідний формат звуку не використовуються.

Успішна генерація й ненульовий PCM не доводять правильної вимови. Перед поширенням потрібне прослуховування літер, їхніх початків/закінчень та швидкості в NVDA. Автоматичні тести доставки банків використовують явно позначені тестові зразки і не видаються за такі акустичні перевірки.

Виключені з поточного випуску голоси блокуються в каталозі, під час установлення голосового пакета та на межі запиту до акустичного робітника. Новий пакет не може обійти це обмеження тим самим ідентифікатором.

Linux-перевірки пакування й передачі профілів адаптерам не замінюють перевірку реального звуку у Windows/NVDA.
