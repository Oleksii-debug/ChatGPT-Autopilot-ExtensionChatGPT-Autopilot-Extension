# Збирання та встановлення модульних пакетів dordiai-voices

Версія наступного збирання: `0.13.1-dev.5`. Позначка `dev` означає збірку для перевірки. Саме створення архіву та успішна перевірка його контрольних сум не підтверджують правильність звучання, роботу Windows DLL або сумісність із живою NVDA.

## Відтворюване збирання

Потрібен Python 3.11 або новіший. Рушії синтезу для пакування не запускаються. Великі вихідні ресурси містяться в `packages/0.12.2`, а оновлений код і невеликі дані — у `source/0.12.2`. Вихідна папка та початкові архіви не змінюються.

З кореня репозиторію:

```text
python dordiai-voices/tools/build_release.py
```

Збирач створює в `dordiai-voices/dist`:

- `dordiai-voices-0.13.1-dev.5.nvda-addon` — основний додаток NVDA, спільні рушії, дозволені голосові ресурси та початковий мовний комплект.
- `dordiai-european-piper-0.13.1-dev.5.zip` — додаткові європейські моделі Piper.
- `dordiai-slovak-rhvoice-0.13.1-dev.5.zip` — словацький рушій RHVoice з необхідними даними.
- `dordiai-wide-languages-0.13.1-dev.5.zip` — наявні додаткові мовні ресурси різних рушіїв.
- `release-build.json` — точний склад, SHA-256, розміри завантаження та встановлених даних і перелік вилучених голосових файлів.

Додаткові пакети відображають наявні ресурси вихідного пакета. Вони самі по собі не доводять готовність усіх 135 вибраних пунктів каталогу. Для цього потрібні окреме зіставлення мовних ресурсів і перевірка вимови.

Для збирання лише ядра:

```text
python dordiai-voices/tools/build_release.py --only core
```

Параметри `--baseline`, `--source`, `--output`, `--version` дозволяють явно задати вхідні папки, вихідну папку та версію. `--only` можна повторювати для груп `core`, `european-piper`, `slovak-rhvoice`, `wide-languages`.

Пакування детерміноване: порядок записів, час у ZIP та перетворення JSON фіксовані. Для однакових незмінних вхідних файлів у тому самому середовищі утворюються однакові архіви. Не редагуйте вихідний код під час фінального збирання. Версія zlib може впливати на зовнішні байти ZIP між операційними системами; для порівняння таких збірок додатково звіряйте SHA-256 кожного файла та знімка джерел. Checkout має зберігати початкові байти файлів без автоматичного перетворення закінчень рядків.

Незмінний знімок попередньої збірки `0.13.1-dev.1`, включно з компактними ресурсами визначення мови та назв символів, збережено в `evidence/source_snapshot_0.13.1-dev.1.json.gz`. Великі акустичні моделі до цього знімка не входять. Поки основна розробка рухається далі, відтворити зафіксований вихідний код можна так:

```text
python dordiai-voices/tools/restore_source_snapshot.py --snapshot dordiai-voices/evidence/source_snapshot_0.13.1-dev.1.json.gz --output dordiai-voices/source/0131-restored
python dordiai-voices/tools/build_release.py --source dordiai-voices/source/0131-restored --version 0.13.1-dev.1
```

Попередню збірку `0.13.0-dev.1` збережено окремо. Для її відтворення використовуйте `evidence/dev1_source_snapshot.json.gz` та явно передавайте `--version 0.13.0-dev.1`; типовий номер збирача вже новіший.

Папка відновлення має бути новою. Засіб перевіряє контрольну суму кожного файла й усього дерева та не перезаписує наявні файли.

Для підготовлених нових моделей є загальний `tools/build_resource_pack.py`: він приймає папку ресурсів, точний шлях призначення під `kx47Runtime/models`, ідентифікатор, версію, мови, рушії та залежності. Нову мову не потрібно окремо дописувати в код збирача. Наявність пакета не доводить наявності відповідного акустичного адаптера: мінімальна версія ядра має відповідати версії, яка справді підтримує модель.

Збірки `0.13.1-dev.1` і `0.13.1-dev.3` та їхні знімки залишаються незмінними. Поточний `0.13.1-dev.5` містить виправлення запуску дочірнього рушія під NVDA. Мінімум нових Rasa/Matcha залишається `0.13.1-dev.3`, оскільки цей номер визначає сумісність акустичних адаптерів.

Проміжний `0.13.1-dev.2` створювався лише для CI до остаточної інтеграції нових адаптерів. Пакети Rasa та Matcha вимагають щонайменше `0.13.1-dev.3`, тоді як раніше створені MMS, Extra та Omni зберігають свій мінімум `0.13.1-dev.1`.

## Нові окремі мовні моделі

`tools/build_prepared_model_packs.py` пакує підготовлені ресурси з `model-packs` в окремі ZIP під `dist/language-packs`. Групи `mms`, `extra`, `rasa` та `omni` вибираються повторюваним параметром `--group`. Вони не входять до початкового ядра. Мінімальна версія вказана для кожного пакета: старі моделі потребують `0.13.1-dev.1`, нові Rasa та Matcha — `0.13.1-dev.3`.

Фактично зібрано 29 окремих пакетів MMS, сім пакетів Extra, окремий Rasa для бодо та спільну експериментальну модель Omni із десятьма малими пакетами мовних опор. Із 48 архівів каталог пропонує 45: три альтернативні опори Omni неактивні, оскільки для цих мов вибрані швидші окремі моделі. Відомості та контрольні суми містяться в `evidence/new_resource_pack_summary.json` і `evidence/new_resource_catalog.json`.

Omni потребує окремого великого спільного пакета та точної його версії. Підготовчий енкодер, тестові WAV і навчальні контрольні точки в користувацькі пакети не входять. Цей рушій експериментальний: повільний синтез не відповідає вимогам швидкого читання NVDA, тому він не вмикається за замовчуванням. Наявність ONNX та успішний синтез ще не підтверджують вимову, клавіатурне відлуння або швидке перемикання.

Rasa використовує лише документований голос BRX_F і стиль ALEXA для бодо. Кашмірський Matcha не підтримує частину символів; вони явно відхиляються або передаються встановленому альтернативному кашмірському рушію. Наявність цих моделей не підтверджує читання назв літер, рідної вимови чи готовність до NVDA.

Кожен пакет містить власні ліцензійні повідомлення. Зокрема, низка нових моделей має умову некомерційного використання; модульність не змінює цих умов.

## Перевірка архівів

```text
python dordiai-voices/tools/verify_release.py dordiai-voices/dist/dordiai-voices-0.13.1-dev.5.nvda-addon dordiai-voices/dist/dordiai-european-piper-0.13.1-dev.5.zip dordiai-voices/dist/dordiai-slovak-rhvoice-0.13.1-dev.5.zip dordiai-voices/dist/dordiai-wide-languages-0.13.1-dev.5.zip
```

Перевіряються точний перелік файлів, розміри, SHA-256, відсутність виключених голосових файлів і відповідність голосового каталогу опису ядра. Архів ядра понад 3 000 000 000 байтів не проходить перевірку. Ціль 2 ГБ оцінюється за фактичним розміром завантаження; встановлені файли та оперативна пам’ять вимірюються окремо.

Контрольні суми в описі забезпечують перевірку цілісності, але не замінюють підпис видавця. Пакети моделей можуть містити потрібні рушіям DLL та EXE; додаткові сценарії Python, PowerShell, CMD і BAT не допускаються.

## Виключені голоси

Збирач прибирає вісім погоджених ідентифікаторів з каталогу, голосових налаштувань, векторів, нативних профілів, літер, команд та навігаційних банків.

Зіставлення точне: ідентифікатор має збігатися з цілою частиною шляху або назвою файла без розширення. Папка `classmate_locales` зберігається, оскільки вона містить спільні ресурси перетворення для дозволених голосів. Схожий підрядок у назві не є підставою для видалення.

Прибирання ключів JSON стосується голосових метаданих. Загальні мовні словники не фільтруються за іменами голосів.

## Встановлення додаткових ресурсів

Після встановлення основного `.nvda-addon` додаткові ZIP-пакети вибираються локально у вкладці «Пакети» налаштувань синтезатора. Їх не потрібно встановлювати як окремі додатки NVDA. Після успішної операції потрібен перезапуск NVDA, щоб каталог установлених моделей перебудувався.

Модуль `kx47Runtime/package_manager.py` надає функції:

- `list_installed_packs(addon_root=None)` — список установлених пакетів без великих переліків файлів.
- `inspect_pack(archive_path)` — структурна перевірка опису та архіву.
- `install_pack(archive_path, addon_root=None)` — перевірка вмісту та встановлення.
- `uninstall_pack(pack_id, addon_root=None)` — видалення тільки власних незмінених файлів пакета.

Встановлювач перевіряє версію ядра за правилами SemVer, залежності, розміри та всі контрольні суми. Для спільних акустичних моделей поле `dependency_versions` фіксує точну версію залежності: встановлення несумісного мовного пакета або оновлення спільної моделі, що зламає вже встановлений пакет, відхиляється. Старі пакети з залежностями лише за ідентифікатором залишаються сумісними. Шляхи обмежені папкою `kx47Runtime/models`. Заборонені вихід за її межі, символьні посилання, дублікати з різним регістром, небезпечні імена Windows, виключені голосові ресурси та заміна файлів ядра або іншого пакета.

Файли спочатку розпаковуються й перевіряються в тимчасовій папці. Під час зміни встановлених файлів ведеться журнал та зберігаються резервні копії. Помилка, зокрема блокування файла Windows, запускає повернення попереднього стану. Після аварійного завершення журнал використовується перед наступною операцією; змінені стороннім процесом файли не видаляються навмання. Якщо відновлення блокує завантажений рушій, необхідно перезапустити NVDA й повторити операцію.

Галочка мови лише вмикає або вимикає її використання. Для звільнення місця на диску користувач окремо видаляє відповідний пакет. Якщо від пакета залежить інший установлений пакет, спочатку потрібно видалити залежний.

## Збереження пакетів під час оновлення ядра

Перед активацією нового додатка `installTasks.onInstall` викликає `upgrade_packages.migrate_installed_packages`. У папку NVDA `.pendingInstall` переносяться лише зареєстровані мовні ресурси та перевірені версії керованих голосових пакетів, включно з вибором активної версії. Старі сценарії Python, невідомі метадані та сторонні файли не копіюються.

Контрольні суми, версії адаптерів, залежності та конфлікти з новим ядром перевіряються до зміни реєстру. Пошкоджений ресурс або несумісне оновлення зупиняє встановлення; попередні моделі та їхні реєстри залишаються на місці. Якщо нове ядро вже містить ідентичний ресурс, він не стає власністю додаткового пакета й не видаляється разом із ним. Повторний запуск перенесення не створює дублікати.

Перевірка перенесення й виклику інсталяційного hook:

```text
python -m unittest discover -s dordiai-voices/tests -p test_upgrade_packages.py -v
```

## Перевірки коду пакування

```text
python -m unittest discover -s dordiai-voices/tests -p test_release_build.py -v
```

Ці перевірки охоплюють пакування та безпечне керування ресурсами. Вони не замінюють протокол прослуховування і випробування Windows/NVDA.

## Фактичний розмір збереженої збірки

Незмінне ядро `0.13.1-dev.1` займає 1 766 492 602 байти для завантаження. Сума розпакованих корисних файлів становить 2 125 037 335 байтів; метадані випуску та накладні витрати файлової системи рахуються окремо. Це різні вимірювання, і жодне з них не є споживанням оперативної пам’яті.

Спільні моделі та мовні дані займають 1 259 782 055 байтів, голосові профілі з готовими літерними й навігаційними банками — 687 245 667 байтів, вбудований Python та нативні бібліотеки — 169 471 193 байти. Точні побайтові дублікати дають лише 17 488 453 зайвих байти, тобто приблизно 0,82% розпакованого вмісту. Видаляти їх без збереження шляхів, за якими рушій шукає ресурси, небезпечно. Готові банки також потрібні для швидкого озвучення клавіатури.

Відтворити аудит без завантаження акустичних моделей у пам’ять:

```text
python dordiai-voices/tools/audit_core_size.py dordiai-voices/dist/dordiai-voices-0.13.1-dev.1.nvda-addon --output dordiai-voices/evidence/core_size_audit_0.13.1-dev.1.json
```

## Артефакти перевірки GitHub Actions

Workflow `dordiai-voices.yml` не публікує випуск автоматично. Після збирання він завантажує ядро, кожен із трьох додаткових пакетів і протоколи Windows/NVDA в окремі артефакти GitHub Actions на сім днів. Посилання й фактичні розміри архівів додаються до підсумку запуску. Для завантаження артефактів потрібно ввійти в GitHub.

Артефакти мають позначку `development`; наявність файла для завантаження не означає успішного завершення перевірок. Необхідно читати протоколи та стан відповідного запуску. Розділення артефактів дозволяє завантажити лише основний додаток, не завантажуючи всі додаткові моделі.

## Резервне збереження великого ядра

Якщо сховище не приймає цілий `.nvda-addon`, `tools/create_core_backup.py` створює чотири окремі коректні ZIP без додаткового стиснення. Кожен ZIP менший за 450 000 000 байтів і містить один послідовний блок початкового файла. Це резервні частини, а не окремі інсталятори NVDA.

Команда приймає `--source`, нову папку `--output`, `--version` та обов’язкову контрольну суму `--expected-sha256` із перевіреного звіту випуску. Параметр `--evidence` зберігає компактний звіт. Джерело не змінюється; повторне використання наявної вихідної папки відхиляється. Перед публікацією резервної папки засіб повторно читає всі ZIP та перевіряє остаточну контрольну суму без створення другої великої копії ядра.

Окремий малий `backup-tools.zip` містить упорядкований опис JSON, автономний `restore_core_backup.py` та інструкцію. Відновлювач потребує лише стандартного Python, перевіряє контрольні суми архівів, блоків і всього ядра, відхиляє переставлені частини та небезпечні шляхи й атомарно створює кінцевий файл. Наявний інший файл не перезаписується. Режим `--verify-only` перевіряє резервну копію потоково без великого вихідного файла.

## Продовження розробки без початкового архіву Drive

Перевірений повний файл ядра, зокрема відновлений із чотирьох резервних ZIP, можна перетворити на мінімальну ресурсну базу для наступного збирання. Початковий архів на 8 ГБ і папка `packages/0.12.2` для цього не потрібні:

```text
python dordiai-voices/tools/recover_core_baseline.py --archive dordiai-voices/dist/dordiai-voices-0.13.1-dev.4.nvda-addon --output dordiai-voices/packages/recovered-core-dev4 --expected-sha256 b80f0f2a428ba097b37437ccfd028ce41630b73fd92c5cfa9539da1b08a1b90e
```

Засіб спочатку перевіряє очікувану контрольну суму архіву, метадані ядра та SHA-256 кожного корисного файла. Лише потім він копіює дані в нову тимчасову папку, ще раз перевіряє байти й атомарно публікує готову базу. Код із архіву не запускається. Згенерований `dordiai-release.json` не переноситься у вхідні файли наступної збірки. Наявна база не перезаписується; кількість голосів береться з фактичного перевіреного каталогу, без вимоги початкових 53 профілів.

Далі відновіть потрібний новіший знімок джерел засобом `restore_source_snapshot.py` у нову папку та передайте її як `--source`, а відновлену ресурсну базу — як `--baseline` до `build_release.py --only core`. Номер наступної збірки задайте явно через `--version`. Тести перевіряють як побайтове відтворення попереднього ядра, так і накладання новішого коду зі збереженням акустичних ресурсів.

Така база зберігає лише ресурси, що реально входили до резервного ядра: рушії, початкові мови, голосові профілі та підготовлені банки. Відсутні додаткові пакети Piper, Wide та Slovak вона не відновлює. Для них потрібні власні збережені ZIP; окремі збережені нові мовні пакети також встановлюються незалежно.

Фактична перевірка `evidence/recovered_core4_to_dev5_rebuild.json` підтвердила: ядро `0.13.1-dev.5`, зібране з відновленого ядра `0.13.1-dev.4` та нового знімка джерел, побайтово збігається зі збіркою з повної початкової бази. Малий `dist/dordiai-core-resume-0.13.1-dev.5.zip` містить новий знімок, автономні засоби й інструкції, але не акустичні ваги. Разом зі збереженими чотирма частинами ядра dev4 він дозволяє відновити dev5 без початкового Drive.
