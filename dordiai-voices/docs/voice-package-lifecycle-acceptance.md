# Actual NVDA voice package lifecycle acceptance

This is the planned acceptance scenario after the reviewed ownership fix enters a new immutable core. It has not run against source12. The isolated candidate gate proves Windows file/registry behavior; it does not prove NVDA GUI accessibility or audible output.

Use a disposable Windows NVDA configuration and the new core's exact size/SHA/source pin. Preserve the source12 archive unchanged. Reuse one permitted installed profile to prepare two data-only immutable package versions with the existing adapter/CLI, exact file hashes and recorded fixture provenance. Do not add an excluded identity. Record the chosen ID and all package/core hashes. Do not distribute the temporary fixture packages as new voices.

1. Save a real NVDA profile, enable its working languages, select the target voice, and speak a fixed sentence. Open the actual preferences window through NVDA+Ctrl+Shift+F10. Navigate tabs, package list and buttons by keyboard; record real focus/name/role/state events.
2. Install fixture version1 from the actual file chooser. The settings operation must select built-in eSpeak before retiring dordiai workers. Record that keyboard navigation remains spoken by eSpeak, worker handles close before file changes, and a fresh dordiai instance returns with saved settings after completion. Verify installed manifest/assets and speak the fixed sentence through the selected imported profile.
3. Install version2 for the same ID. Verify version1 remains byte-identical and available for rollback; verify version2 is the active adapter resource. Reopen settings and choose version1 through the installed-version button. Verify the active index, actual loaded asset identity and spoken sentence after driver replacement.
4. Attempt a corrupt/incompatible package through the file chooser. Verify the original active data/index remain unchanged, the error is accessible and a fresh working driver returns. An operation error must not be replaced by a success notice.
5. Exercise a real Windows file lock during removal after worker retirement. The operation must fail visibly; the voice becomes inactive and remains in the actual package list. Verify no speech request loads the damaged/inactive package. Close the external lock, choose the retained row and retry deletion. Verify all owned files and the ownership record disappear, unrelated voices/core files remain, and a working language/voice is selected.
6. Separately retain a complete inactive version in the disposable configuration. The actual dialog must label it inactive and offer its sole installed version for verified activation. Activate it and verify the voice works; no ambiguous active/inactive ownership may remain.
7. Restart NVDA and switch between two saved configuration profiles. Verify language/voice selections and package availability survive; unchecking a language must not delete data. Verify at least one working selection remains after removing the optional voice.
8. Perform an actual add-on upgrade using a second disposable installation containing the verified optional voice versions and inactive ownership. Confirm installTasks migrates into pendingInstall, old data remain unchanged, rollback versions and inactive entries survive, and final restart uses the new core. A damaged retained package must block migration with an actionable cleanup error before replacing old data.

Save a bounded receipt with real UI events, operation result/error, old/new driver identity, worker retirement, profile snapshots, active/inactive index versions, package/asset hashes and post-restart checks. Separate software playback events from actual audio-device capture and human pronunciation acceptance. Keep product_ready=false unless the full product specification has independent evidence.
