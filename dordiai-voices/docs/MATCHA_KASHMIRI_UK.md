# Кашмірська: власний мовний тракт Bolbosh / Matcha

Додатковий пакет містить справжню модель кашмірської мови з персо-арабським
письмом. Вона навчалася на кашмірських записах. Її не підмінено урду, гінді
або фонетичним перетворенням іншої мови. Голос користувача накладається
окремо через наявний OpenVoice, як і для інших мовних носіїв.

Основні джерела:

- [Код Bolbosh, MIT](https://github.com/gaash-lab/Bolbosh),
  ревізія `7435b77029a691cc00a335356013ca6ee78f794a`.
- [Ваги GAASH-Lab/Matcha-TTS-Kashmiri, MIT](https://huggingface.co/GAASH-Lab/Matcha-TTS-Kashmiri),
  ревізія `718203e01e0b4ddab3e925445619c69cddeb7231`.
- [KashmiriNormalizer, MIT](https://github.com/abdulmuizz0903/KashmiriNormalizer),
  ревізія `9bb966e76b88caf875bfb9facf3036bef706427e`.
- [Праця авторів](https://arxiv.org/abs/2603.07513).
- Універсальний HiFi-GAN v1 з офіційного випуску
  `shivammehta25/Matcha-TTS-checkpoints`, SHA256
  `771eaf4876485a35e25577563d390c262e23c2421e4a8c929eacfde34a5b7a60`.

Кінцевий ONNX-файл має 141 748 312 байтів та вже містить вокодер.
Для користувача не потрібні PyTorch, Lightning, Diffusers або окремий G2P.
Мінімальна версія ядра — `0.13.1-dev.2`. Модель розміщується в
`kx47Runtime/models/ExtraLanguages/ks` і не збільшує базовий пакет для всіх.

Повторюване складання:

```sh
python tools/prepare_matcha_models.py --download-only
# Наступна команда запускається в окремому середовищі підготовки з CPU PyTorch.
python tools/prepare_matcha_models.py --export-offline
# Підготовка голосового відбитка потребує лише NumPy, SoundFile та ORT1.27.
python tools/prepare_matcha_models.py --prepare-runtime
```

107 вихідних файлів мають окремі URL, розміри та SHA256 у
`tools/matcha_checkpoint_sources.json`. Завантаження та виконання моделей
розділені. У режимах offline відсутній або змінений файл спричиняє помилку.
Ваги читаються через `weights_only=True`, з явно переліченими відомими
контейнерами OmegaConf у метаданих. Навчальні оптимізатор і вирівнювання
не запускаються. Усі ваги акустичної моделі завантажуються строго.

Фактична перевірка ONNX охопила різну довжину тексту, два справжні голоси
носія 422/423 і подвійну швидкість. Довжини збігаються з PyTorch,
косинус подібності хвиль — близько одиниці. Перед експортом скидається
кеш RoPE, щоб довший текст не залежав від довжини прикладу під час трасування.
Журнал перевірок: `evidence/matcha_export.json`.

Відбиток `source.npy` виміряний FP32-енкодером OpenVoice із фактичної
PCM16-хвилі цього самого кашмірського носія. Відбиток іншої мови не копіюється.
Джерело, хеш хвилі та енкодера збережено у `runtime_config.json` і
`evidence/matcha_preparation.json`.

Пакет залишається експериментальним. У справжньому словнику моделі відсутній
кашмірський знак `ٲ` (U+0672). Початковий нормалізатор мовчки його видаляє;
наш адаптер повертає явну помилку. Це стосується також цифри вісім, оскільки
її правильна назва містить цей знак. За наявності окремо встановленої
кашмірської Omni можна явно використати її для такого запиту. Інша мова
не використовується як непомітна заміна.

Звичайні назви літер, правильність вимови носіями та робота у Windows/NVDA
ще не прийняті. Технічна перевірка хвиль не дорівнює такому прийманню.
Виміряні швидкості наведено в журналі для конкретного процесора; вони
не є обіцянкою миттєвого читання кожного невідомого слова.
